DOMjudge 대회 통합 운영 매뉴얼

DOMjudge 설치 이후 대회를 세팅하고, 운영하며, 종료 후 마무리하기까지의 전체 워크플로우를 안내합니다. 영문 공식 매뉴얼 (한국어 비공식 매뉴얼)과 병행하여 참고해주세요.

⚙️ Step 1. 사전 준비 — 시스템 점검 (Admin)

운영진 권한 구분

DOMjudge는 아래 네 가지 역할을 제공합니다. 감독 교사에게는 jury 권한을 부여하는 것을 권장합니다.

권한 역할
admin 전체 시스템 관리 (모든 설정 접근 가능)
jury 스코어보드 + 제출 현황 열람, Clarification 답변 — 감독 교사용 권장
balloon 풍선 배달 담당 (정답 팀 추적, 선택적 운영)
team 일반 참가자 (문제 열람 및 코드 제출)
Judgehost(채점기) 연결 확인

'Admin' → 'Judgehosts' 메뉴에서 모든 채점기가 active 상태인지 확인합니다. 하나라도 비활성화되어 있으면 채점 지연이 발생할 수 있으므로 대회 전 반드시 점검하세요.

🐍 Python 언어 Time factor 설정

Python은 C/C++에 비해 실행 속도가 느리므로 시간제한에 배수를 적용해 불이익을 방지합니다.

  1. Admin → Languages → Python3 항목 클릭
  2. Time factor 필드에 1.5 입력 후 저장
예: 문제 시간제한이 2초인 경우 → Python 참가자에게는 자동으로 3초가 적용됩니다.

📅 Step 2. 대회(Contest) 생성

'Admin' → 'Contests' 메뉴에서 새 대회를 생성합니다. 아래 항목들을 순서대로 입력하세요.

필드 예시 값 설명

Shortname gfpc-test-1 URL 및 내부 식별자로 사용됩니다. 영문 소문자·숫자·하이픈만 허용합니다.
Name 2026 GFPC 테스트 1회 참가자 화면에 표시되는 대회 이름입니다.

예: -0:10 (Start 10분 전)  /  +2:00 (Start 2시간 후)

필드 예시 값 설명
Activate time -0:10 대회 이름 등 기본 정보가 참가자 화면에 노출되기 시작하는 시간입니다. 아직 문제는 보이지 않습니다.
Start time 2026-06-17 20:00:00 Asia/Seoul 절대 시각만 허용. 문제 열람과 코드 제출이 가능해지는 대회 공식 시작 시간입니다. 나머지 필드의 상대 시각은 이 시각을 기준으로 계산됩니다.
Freeze time +1:30 순위판 동결 시작 시각입니다. 이후 제출은 채점되지만 스코어보드에는 반영되지 않습니다. 종료 30분 전 설정을 권장합니다.
End time +2:00 대회가 종료되고 코드 제출이 차단되는 시간입니다.
Unfreeze time +2:30 동결된 순위판이 공개되는 시간입니다. 시상식 직전에 맞추면 최종 순위가 극적으로 공개됩니다.
Deactivate time +168:00 대회 페이지 자체가 비활성화되어 참가자가 더 이상 접근할 수 없게 되는 시간입니다. (Start 기준 7일=168시간 후)
💡 팁: 상대 시각을 사용하면 Start time만 수정해도 Freeze · End · Unfreeze가 자동으로 따라옵니다. 현장에서 시작 시각을 앞당길 때 특히 편리합니다.
기타 설정 — 아래 값은 기본값 그대로 활용
필드 권장 값 설명
Scoreboard type pass-fail 정답/오답만 구분하는 ICPC 방식입니다. 일반 코딩 대회에는 이 설정을 사용합니다.
Allow submit Yes 팀의 코드 제출을 허용합니다.
Record balloons Yes 정답 팀에 대한 풍선 기록을 활성화합니다. 풍선 배달을 운영하지 않더라도 켜두어도 무방합니다.
Runtime as tiebreaker No 동점 시 실행 시간으로 순위를 결정하는 옵션입니다. 일반 대회에서는 사용하지 않습니다.
Medals enabled No ICPC 스타일 메달 표시 기능입니다. 일반 대회에서는 비활성화합니다.
Enable public scoreboard Yes 로그인 없이 외부에서 스코어보드를 열람할 수 있도록 공개합니다.
Open contest to all teams Yes 등록된 모든 팀이 이 대회에 참가할 수 있도록 허용합니다.
Languages 비워두기 비워두면 시스템에 등록된 모든 언어를 허용합니다. 특정 언어만 허용하려면 직접 선택합니다.
Enable contest Yes 대회를 활성화합니다. 비활성화하면 Activate time이 지나도 노출되지 않습니다.
💡 팁: 대회 생성 후 'Admin' → 'Contests' → 해당 대회 클릭 → Problems 탭에서 문제를 연결합니다. 문제 연결은 Step 4에서 진행합니다.

📄 Step 3. 팀/계정 일괄 등록 (JSON)

팀이 많을 경우 Python 스크립트로 엑셀을 JSON 파일로 변환한 뒤, Admin → Import/Export에서 한 번에 등록할 수 있습니다. 기존 TSV 방식보다 더 많은 정보(카테고리, 소속, 위치 등)를 한꺼번에 등록할 수 있습니다.

excel2domjudge 스크립트 다운로드

엑셀(xlsx) → DOMjudge JSON 변환 도구입니다. Python 3.8 이상 환경에서 실행하며, 필요한 패키지(openpyxl)는 최초 실행 시 자동 설치됩니다.

⬇ excel2domjudge.zip
① 템플릿 엑셀 생성

ZIP을 압축 해제한 폴더에서 아래 명령어를 실행하면 domjudge_templates.xlsx 파일이 생성됩니다.

python excel2domjudge.py --template
② 엑셀 작성 (4개 시트)

생성된 엑셀을 열면 4개의 시트가 있습니다. 회색 예시 행을 참고해 실제 데이터를 입력한 뒤 예시 행은 삭제합니다.

시트 내용 주요 필드
groups 팀 카테고리
예: 고등부, 대학부		 id, name, hidden, sortorder
organizations 소속 기관
예: 학교별 정보		 id, name, formal_name, country
teams 팀 목록 id, name, group_ids★, organization_id★
accounts 로그인 계정 목록 id, username, password, type, team_id★

★ 표시 필드는 다른 시트의 id 값을 참조합니다. 엑셀에서 드롭다운으로 선택할 수 있습니다.

③ JSON 변환 실행

엑셀 파일을 저장하고 닫은 뒤 실행합니다. result/ 폴더에 JSON 파일 4개가 생성됩니다.

python excel2domjudge.py

오류가 있으면 행 번호와 원인이 출력되므로 엑셀을 수정 후 다시 실행합니다. 시트 간 참조 오류(예: 존재하지 않는 group_id) 도 자동 검사합니다.

④ DOMjudge에 Import

브라우저에서 http://<domjudge-ip>/jury/import-export로 접속한 뒤, Teams & groups → Import JSON / YAML 섹션에서 아래 순서대로 Type을 선택하고 해당 파일을 업로드합니다. 순서를 반드시 지켜야 합니다.

순서 Type 선택 업로드 파일
1 groups 1-groups.json
2 organizations 2-organizations.json
3 teams 3-teams.json
4 accounts 4-accounts.json

⚠ 주의사항

  • 엑셀을 반드시 닫은 뒤 스크립트를 실행하세요. 파일이 열려 있으면 읽기 오류가 발생합니다.
  • Import 순서 준수: groups → organizations → teams → accounts 순서를 지키지 않으면 참조 오류로 등록이 실패합니다.
  • id 중복 금지: 각 시트 내 id 값은 고유해야 합니다. 중복 시 스크립트가 오류를 출력하고 중단됩니다.
  • accounts type: team, judge, admin, balloon 중 하나만 허용됩니다.

📝 Step 4. 문제(Problems) 추가 및 라벨 지정

문제 ZIP 패키지 제작 방법은 앞의 문제(Problem) 준비 페이지를 참고하세요. 준비된 패키지를 'Admin' → 'Problems'에서 먼저 업로드한 뒤, 'Admin' → 'Contests' → 해당 대회의 ✏️ 편집 버튼 → Problems 탭에서 문제를 대회에 연결합니다.

필드 설명
Short name 스코어보드에 표시되는 문제 라벨입니다. a, b, c 순으로 입력하면 A, B, C로 표시됩니다.
Points 문제 배점입니다. 일반 ICPC 방식 대회에서는 1로 설정합니다. 배점제를 사용하지 않으면 모든 문제를 동일하게 1점으로 두면 됩니다.
Allow submit 팀의 해당 문제 제출 허용 여부입니다. 기본값 Yes를 그대로 사용합니다.
Allow judge 채점기의 자동 채점 허용 여부입니다. 기본값 Yes를 그대로 사용합니다.
Colour 스코어보드에 표시되는 문제 색상입니다. 풍선 배달 운영 시 색상을 지정하면 편리합니다. 선택 사항입니다.
Lazy eval 이미 오답으로 확정된 제출의 나머지 테스트 케이스를 건너뛰는 옵션입니다. 채점 속도가 빨라지므로 기본값 Default를 그대로 사용합니다.

📋 Step 5. 리허설 체크리스트 (대회 전날)

대회 전날 리허설 시 아래 항목을 점검합니다. 당일 본대회 직전이 아니라 하루 전에 문제를 발견하고 수정할 여유를 확보하는 것이 목적입니다.

  • 🧊 점수판 동결 (Freeze): 대회 종료 30분 전부터는 순위를 숨길 수 있습니다. Unfreeze를 시상식 직전 수동으로 실행하면 최종 순위가 한꺼번에 공개되어 극적인 효과를 연출할 수 있습니다.
  • ⏱️ 패널티 규칙: 오답 1회당 패널티 20분 적용 여부와 순위 산정 방식을 확인합니다. 순위는 ① 정답 문제 수 → ② 패널티 합계(정답 처리된 문제의 제출 시각(분) + 오답 횟수 × 20분) 순으로 결정됩니다.
  • ✅ Judgehost 확인: 'Admin' → 'Judgehosts'에서 모든 채점기가 active 상태인지 확인합니다.
  • 🔗 문제 연결 확인: 'Admin' → 'Contests' → Problems 탭에서 모든 문제가 올바르게 연결되어 있는지 점검합니다.

🧪 Step 6. 데모 대회 운영 (대회 당일)

본 대회 전에 별도 Demo용 Contest를 생성하여 참가자들이 시스템에 익숙해질 수 있도록 연습 시간을 제공합니다.

📝
연습 문제 연결

Hello World, 두 수의 합 등 간단한 문제 1~2개를 별도 Contest에 연결합니다. 본 대회 문제는 포함하지 않습니다.

👥
기존 계정 그대로 사용

데모 대회에서도 본 대회용 팀 계정을 그대로 사용합니다. 별도 계정 생성이 필요 없습니다.

⏰
여유 있게 운영

Freeze 없이 여유 있게 운영합니다. 데모 종료 후 본 대회 Start 시간을 실시간으로 조정하여 시작합니다.

💡 팁: 데모 대회 중 참가자 제출이 정상적으로 채점되는지 반드시 확인하세요. 채점 결과가 돌아오지 않으면 본 대회 전에 Judgehost 상태를 재점검합니다.

👨‍💻 Step 7. 대회 진행 및 학생 참여 가이드

학생들은 Team Member 역할을 통해 로그인하고 대회를 치릅니다. 관리자(Jury)는 대회가 진행되는 동안 시스템을 모니터링해야 합니다.

1. 로그인 및 문제 열람

학생은 부여받은 계정으로 접속하여 'Problemset' 메뉴에서 문제를 확인합니다.

2. 코드 작성 및 제출

로컬 환경에서 코드를 작성한 후, 'Submit' 버튼을 눌러 소스 코드를 업로드합니다.

3. 결과 확인 (Scoreboard)

채점 결과는 실시간으로 반환되며, 스코어보드를 통해 자신의 순위와 결과를 확인합니다.

Jury Task
4. 질의응답 (Clarifications) 처리

관리자는 대회 중 발생하는 모호한 점이나 오류 등에 대한 학생들의 질문(Clarifications 큐)을 실시간으로 모니터링하고 답변해야 합니다. 문제 오류 발견 시 운영진이 먼저 전체 공지로 발송할 수 있습니다.

🛠️ Step 8. 대회 종료 후 사후 관리 (Admin)

🔍
1. 채점 결과 리뷰 및 재채점(Rejudge)

모든 문제의 채점(Judgment) 결과를 검토합니다. 서버 오류나 테스트 케이스 이상으로 잘못 채점된 건이 있다면 아래 방법으로 재채점합니다.

  • 문제 전체 재채점: Admin → Problems → 해당 문제 클릭 → Rejudge all submissions
  • 특정 제출만 재채점: Admin → Submissions → 해당 제출 클릭 → Rejudge
  • 완료 확인: Judging queue가 비워지면 스코어보드에 자동 반영됩니다.
🏆
2. 리더보드 정리 (Unfreeze)

시상식 직전 Unfreeze를 실행하면 동결되었던 최종 순위가 한꺼번에 공개됩니다. 이 순간을 시상식 하이라이트로 활용할 수 있습니다.

🗄️
3. 데이터 백업 및 보관

모든 문제 셋, 제출된 소스 코드, 최종 스코어보드 등은 대회 종료 후 아카이빙하여 추후 참고 자료나 감사 용도로 보관합니다.

📊 Step 9. 시상 통계 추출

대회 종료 후 운영진 PC에서 내부망으로 DOMjudge REST API를 호출하면 제출 기록 전체를 수집할 수 있습니다. Python 스크립트로 데이터를 가공하여 Excel 시상 자료를 자동 생성합니다. DOMjudge 서버의 내부망 IP만 있으면 실행 가능합니다.

🥇 일반 시상 항목

  • •종합 1~3등 — 정답 수 + 패널티 합계 기준
  • •학교별 최고 순위 팀 — 모든 참가 학교 시상 가능
  • •학교별 총 정답 수 1위 — 소속 팀 정답 수 합산

🎨 창의 시상 항목

  • 🏆끈기상 — 오답을 가장 많이 받고도 결국 정답을 낸 팀
  • 🔥열정상 — 정답 0개지만 제출을 가장 많이 한 팀
  • ⚡선빵상 — 대회 시작 후 가장 빨리 첫 정답을 낸 팀
