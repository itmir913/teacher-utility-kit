네트워크 망 구성

대회 중 네트워크 장애는 채점 결과의 신뢰성을 떨어뜨립니다. 아래 네 가지 원칙을 지키면 수십 대의 노트북이 동시 접속해도 안정적으로 운영할 수 있습니다.

DHCP는 하나만

공유기(라우터) 한 대에서만 DHCP를 활성화합니다. AP의 DHCP는 반드시 비활성화해야 IP 충돌이 없습니다.

AP는 브릿지 모드

AP를 라우터 모드로 두면 이중 NAT가 발생해 학생 노트북이 DomJudge 서버에 접근하지 못합니다. 반드시 브릿지(AP) 모드로 설정하세요.

채널 간섭 방지

AP 여러 대를 배치할 때 5GHz 채널은 36 / 100 / 149를 순환 배정합니다. 이 세 채널은 서로 겹치지 않습니다.

서버는 반드시 고정 IP

DomJudge 서버와 judgehost 서버는 DHCP 예약 또는 정적 IP로 설정합니다. IP가 바뀌면 judgehost 연결이 끊깁니다.

⚠ AP 브릿지 모드 설정 실수 최다 원인

공유기를 교체하거나 초기화했을 때 AP 설정이 함께 초기화되어 DHCP가 켜지는 경우가 많습니다. 대회 당일 전 반드시 AP 관리 페이지에 접속해 동작 모드를 재확인하세요.

대역 및 장비별 IP 배정 계획

192.168.1.0/24 대역 기준. 공유기에서 DHCP 범위를 .50~.200으로 설정하고, 서버·AP는 정적 IP로 지정합니다.

장비 IP 주소 할당 방식 비고
공유기 (게이트웨이) 192.168.1.1 고정 DHCP 서버 · NAT · 인터넷 출구
DomJudge 메인 서버 192.168.1.10 고정 nginx · MariaDB · API
judgehost #1 192.168.1.11 고정 채점 전용 데몬
judgehost #2 192.168.1.12 고정 채점 전용 데몬
AP #1 192.168.1.21 브릿지 5GHz ch36 · SSID: contest
AP #2 192.168.1.22 브릿지 5GHz ch100 · SSID: contest
학생 노트북 192.168.1.50 ~ .200 DHCP 최대 150대

구성도 1: 기본 구성 단일 AP + DomJudge

가장 단순한 형태입니다. 공유기 아래 L2 스위치를 두고, DomJudge 서버와 AP 1대를 각 포트에 연결합니다. AP 1대에서는 대략 최대 30대의 학생 노트북을 수용합니다.

AP 브릿지 모드란?

AP가 라우터(DHCP 포함) 역할 없이 무선 신호 ↔ 유선 변환만 담당하는 모드입니다. 공유기가 DHCP를 전담하므로 IP 충돌 없이 하나의 서브넷으로 모든 장비가 통신합니다.

구성도 2: 다수 AP 배치 학생 60~90명 규모

AP 1대에 30대가 한계입니다. 교실·강당 규모로 60~90명을 수용하려면 AP를 3대 이상 배치합니다. 모든 AP는 같은 스위치에 연결하고 SSID를 동일하게 설정하면 학생 노트북이 가장 강한 신호의 AP로 자동 접속합니다.

같은 SSID, 다른 채널로 원활한 로밍

3대 AP 모두 SSID를 contest로 동일하게 설정하면, 학생 노트북이 교실 내 위치에 따라 신호가 강한 AP로 자동 접속(로밍)됩니다. 별도 컨트롤러 없이도 동작합니다.

구성도 3: 다중 judgehost 확장 대규모 · 다중 채점

참가자가 많아지면 채점 큐가 밀립니다. judgehost 전용 서버를 추가하면 메인 서버의 부하를 줄이고 채점 처리량을 선형으로 늘릴 수 있습니다. 메인 서버는 웹/DB/API만 담당하고, judgehost 서버들이 실제 코드 실행과 채점을 분담합니다.

judgehost 추가 방법

추가할 리눅스 서버에 Docker를 설치하고, docker-compose.yml 파일의 DOMSERVER_URL을 메인 서버 API 주소(예: http://[메인서버IP]/api)로 설정하면 됩니다. DomJudge 어드민 화면에서 자동으로 등록된 judgehost를 활성화할 수 있습니다.

AP 브릿지 모드 설정 절차

AP 제조사마다 메뉴 이름이 다르지만 아래 순서로 찾아서 설정합니다. 공통적으로 "동작 모드 → AP 모드 or 브릿지 모드"와 "DHCP 서버 → 비활성화" 두 항목이 핵심입니다.

1
AP 관리 페이지 접속

AP의 기본 IP (보통 192.168.1.1 또는 AP 하단 스티커 참고)로 브라우저에서 접속합니다. 대회 전날 반드시 확인하세요.

2
동작 모드 변경

무선 설정 → 동작 모드 → AP 모드 (또는 브릿지 모드) 선택. 라우터 모드, 공유기 모드는 선택하지 않습니다.

3
DHCP 서버 비활성화

LAN 설정 → DHCP 서버 → 비활성화. 이 단계를 빠뜨리면 IP 충돌로 학생 노트북이 DomJudge에 접속하지 못합니다.

4
SSID 및 채널 설정

SSID: contest (암호는 대회 규정에 따라 설정). 5GHz 채널은 AP별로 36 / 100 / 149 순으로 배정. 자동 채널 선택은 사용하지 않습니다.

5
AP 자체 IP 고정

AP 관리 IP를 공유기 DHCP 범위 밖으로 고정합니다. 예: 192.168.1.21. 그래야 재부팅 후에도 관리 페이지에 항상 접속할 수 있습니다.

⛔ 절대 하면 안 되는 것

AP에서 DHCP를 켜둔 채 운영하면 공유기와 AP 두 곳에서 IP를 나눠주게 됩니다. 이 경우 일부 노트북은 AP가 준 IP를 받아 다른 서브넷으로 분류되고, DomJudge 서버에 접근하지 못합니다.

보안 설정: 1. 방화벽 (UFW) 설정 ▼

DomJudge 서버에서만 적용합니다. judgehost 서버는 내부망에서만 통신하므로 별도 방화벽 규칙이 필요하지 않습니다. 서비스 운영에 필요한 최소한의 포트만 개방합니다.

내부 네트워크

서버의 고정 IP 할당 및 내부망 통신 확인. judgehost → DomJudge 통신은 내부망이므로 방화벽 불필요.

외부 접속

80(HTTP), 443(HTTPS) 포트 개방 필수. 학생 노트북이 DomJudge 웹 인터페이스에 접속하는 포트입니다.

bash — DomJudge 서버 (192.168.1.10) UFW 
# 기본 방화벽 규칙 설정
sudo ufw default deny incoming
sudo ufw default allow outgoing

# 변경된 SSH 포트 (기본 22 대신 사용)
sudo ufw allow 22222/tcp

# 학생 노트북 접속용 포트
sudo ufw allow 80/tcp   # HTTP
sudo ufw allow 443/tcp  # HTTPS

# 방화벽 활성화
sudo ufw enable
sudo ufw status verbose
보안 설정: 2. Nginx Proxy Manager (SSL) ▼

도메인 연결 및 Let's Encrypt 무료 인증서 적용을 위한 리버스 프록시 설정입니다. 외부에서 HTTPS로 접속할 때 필요합니다. 내부망만 사용하는 경우 생략 가능합니다.

1
Proxy Host 추가

도메인 주소와 내부 IP:포트(192.168.1.10:80) 연결. Forward Hostname에 내부 IP, Forward Port에 80 입력.

2
SSL 인증서 적용

SSL 탭 → Request a new SSL Certificate 선택 → Let's Encrypt 이메일 입력 → Force SSL 체크.

3
Websockets Support 활성화

DomJudge 대시보드의 실시간 채점 현황 업데이트가 WebSocket을 사용하므로, 반드시 활성화합니다.

judgehost 추가 설정 (Docker-Compose) ▼

여러 대의 리눅스 서버를 Judgehost 전용 서버 (채점 전용 추가 서버)로 구성할 수 있습니다. 추가할 리눅스 서버에 Docker를 설치한 후, 아래 설정으로 docker-compose.yml 파일을 생성하여 실행합니다.

docker-compose.yml (추가할 서버용) 설정 
services:
  judgehost:
    image: domjudge/judgehost:9.0.0
    restart: always
    privileged: true
    cgroup: host
    environment:
      - DOMSERVER_URL=http://<메인서버_IP>/api
      - JUDGEDAEMON_PASSWORD=<어드민에서_생성한_패스워드>
      - CONTAINER_TIMEZONE=Asia/Seoul
    volumes:
      - /sys/fs/cgroup:/sys/fs/cgroup:rw
      - judgehost-ids:/shared/daemon-ids
    entrypoint:
      - /bin/bash
      - -c
      - |
        SHARED=/shared/daemon-ids
        mkdir -p $$SHARED

        # 1. 컨테이너 고유 ID 추출
        MY_ID=$$(cat /proc/self/cgroup | grep -o "[a-f0-9]\{64\}" | head -1 | cut -c1-16)

        # 2. 정리 함수
        cleanup() {
            rm -f "$$SHARED/$$MY_ID"
            rm -rf "$$SHARED/lock_$$DAEMON_ID"
            exit 0
        }
        trap cleanup SIGTERM SIGINT

        # 3. DAEMON_ID 할당
        if [ -f "$$SHARED/$$MY_ID" ]; then
            export DAEMON_ID=$$(cat $$SHARED/$$MY_ID)
        else
            for i in $$(seq 0 99); do
                if mkdir "$$SHARED/lock_$$i" 2>/dev/null; then
                    export DAEMON_ID=$$i
                    echo $$i > "$$SHARED/$$MY_ID"
                    break
                fi
            done
        fi

        # 4. 프로세스 실행
        /scripts/start.sh &
        wait $$!

volumes:
  judgehost-ids:
judgehost 실행 및 활성화 실행 
# 컨테이너 실행
docker-compose up -d

# 어드민 웹 접속: Administration → Judgehosts
# 새로 등록된 judgehost 확인 후 "Active" 토글 ON
⚠ 주의사항

메인 서버의 DOMSERVER_URL 주소와 JUDGEDAEMON_PASSWORD가 일치하는지 반드시 확인하세요. 또한, Docker 컨테이너가 정상적으로 메인 서버 API와 통신할 수 있도록 네트워크 방화벽이 허용되어 있어야 합니다.
