문제(Problem) 준비

DOMjudge에 문제를 등록하려면 ICPC 표준 ZIP 패키지 형식으로 제작해야 합니다. 패키지 구조를 먼저 이해한 뒤, 직접 구성하거나 스크립트로 자동 생성합니다.

📦 Step 1. ICPC 문제 패키지 포맷 이해

패키지 디렉토리 구조

각 문제는 아래 구조를 가진 ZIP 파일로 패키징합니다. 한국어 문제의 경우 Docker 환경에서 LaTeX 한글 컴파일이 어려우므로, 외부에서 PDF를 완성한 뒤 삽입하는 방식을 사용합니다.

problem-a/
├── problem.yaml                  ← 문제 메타데이터 (필수)
├── problem_statement/
│   └── problem.pdf               ← 외부에서 제작한 문제지 PDF (필수)
└── data/
    ├── sample/                   ← 공개 예제 (참가자가 sample.zip으로 다운로드 가능)
    │   ├── 1.in
    │   └── 1.ans
    └── secret/                   ← 채점용 비공개 테스트케이스
        ├── 1.in
        └── 1.ans
⚠ 주의: problem.yaml과 data/ 폴더는 필수입니다. problem_statement/problem.pdf가 없으면 문제지가 표시되지 않습니다. 통합 PDF(여러 문제가 하나의 파일)는 사용할 수 없으며, 문제별로 반드시 분리합니다.
problem.yaml 형식

문제 이름과 시간제한을 지정합니다. 시간제한은 초 단위이며, 언어별로 Time factor(시간 배율)가 자동으로 곱해집니다. 기본값은 모두 1배수이고, Python처럼 느린 언어에 배율을 부여하려면 Admin → Languages(/jury/languages)에서 관리자가 직접 수정합니다. (예: Python3 → 1.5배)

name: 문제 이름
timelimit: 2
테스트케이스 구성 규칙
폴더 공개 여부 설명
data/sample/ 공개 참가자가 문제 페이지에서 sample.zip으로 직접 다운로드할 수 있습니다. 로컬에서 직접 테스트할 수 있도록 제공되므로, 반드시 문제 PDF의 입출력 예시와 내용이 일치해야 합니다. 불일치 시 참가자 혼란의 원인이 됩니다.
data/secret/ 비공개 실제 채점에 사용되는 케이스입니다. 참가자에게 노출되지 않습니다. 경계값·대용량 등 다양하게 구성합니다.

파일 이름은 1.in / 1.ans 형식으로 번호를 맞춥니다. 여러 케이스는 2.in / 2.ans, 3.in / 3.ans… 순으로 추가합니다.

✏️ Step 2. 문제 제작

문제를 제작하는 방법은 두 가지입니다. 문제 수가 적거나 테스트케이스 파일이 이미 준비된 경우 직접 구성하고, 문제가 많거나 자동화가 필요하면 스크립트를 사용합니다.

방법 A — 직접 ZIP 구성 (수동)

문제 수가 적거나 별도 도구 없이 빠르게 패키징할 때 사용합니다.

  1. 디렉토리 생성 — Step 1의 구조대로 폴더를 만듭니다. 
    problem-a/
    problem.yaml
    problem_statement/problem.pdf
    data/sample/1.in, 1.ans
    data/secret/1.in, 1.ans, 2.in, 2.ans, ...
  2. problem.yaml 작성 — 문제 이름과 시간제한을 입력합니다.
  3. PDF 삽입 — 외부 편집기(Word, Hwp 등)로 문제지를 작성하고 PDF로 변환한 뒤 problem_statement/problem.pdf로 저장합니다.
  4. ZIP 압축 — problem-a/ 폴더 전체를 ZIP으로 압축합니다.
방법 B — excel2problems 스크립트 (자동)

엑셀에서 문제 내용과 테스트케이스를 작성하면 Word 문서(문제지) 생성 → PDF 변환 → DOMjudge ZIP 패키징까지 자동으로 처리합니다. 문제 수가 많거나 팀원이 함께 작업할 때 적합합니다.

excel2problems 스크립트 다운로드

엑셀(xlsx) → Word(docx) → DOMjudge ZIP 변환 도구입니다. PDF 변환에 Microsoft Word 또는 LibreOffice가 필요합니다.

⬇ excel2problems.zip
1. 템플릿 생성 → 2. 엑셀 작성 → 3. Word 생성 → 4. Word 편집 (선택) → 5. ZIP 패키징
1 템플릿 생성

ZIP 압축 해제 후 아래 명령어를 실행하면 problems_template.xlsx와 problem_template.docx가 생성됩니다.

python 1-excel2docx.py --template
2 엑셀 작성

시트 1개 = 문제 1개입니다. 시트 이름이 problem_id가 되므로 영문으로 작성합니다. (예: aplusb, sort)

처음 사용하거나 전체 흐름을 먼저 테스트하려면, 직접 채우는 대신 아래 명령어로 예시 문제 9개가 채워진 엑셀을 바로 생성할 수 있습니다.

python create_example_problems.py
구역 열 주요 항목
메타데이터 A~B열 name, label, timelimit
문제 설명 D~E열 title, description, input_desc, output_desc
테스트케이스 G~I열 sample / secret 구분 후 입력·출력 작성 (셀 내 줄바꿈: Alt+Enter)
3 Word 문서 생성

엑셀을 저장하고 닫은 뒤 실행합니다. results/docx/에 문제별 .docx 파일이 생성됩니다.

python 1-excel2docx.py
4 Word 편집 선택

results/docx/의 파일을 열어 수식, 그림, 서식 등을 자유롭게 수정합니다. 테스트케이스는 별도 .json 파일에 보관되므로 docx를 수정해도 채점 데이터에는 영향이 없습니다.

5 ZIP 패키징

docx를 PDF로 변환한 뒤 DOMjudge ICPC ZIP 형식으로 패키징합니다. results/{label}-{problem_id}.zip 파일이 문제별로 생성됩니다.

python 2-problems2zip.py

※ PDF 변환에 Microsoft Word 또는 LibreOffice가 설치되어 있어야 합니다.

📂 대용량 테스트케이스 수동 추가 — 5단계 패키징 후 적용

테스트케이스 파일이 너무 크거나 엑셀 셀에 넣기 어려운 경우, 5단계에서 생성된 ZIP 파일에 직접 추가합니다.

  1. 탐색기에서 생성된 .zip 파일을 우클릭 → 압축 프로그램으로 열기
  2. data/secret/ 경로 안에 추가할 .in / .ans 파일을 드래그하여 삽입
  3. 파일명 번호가 기존 케이스와 겹치지 않도록 확인합니다. (예: 기존 1~3이면 4.in부터 추가)

⬆️ Step 3. DOMjudge 업로드

브라우저에서 http://<domjudge-ip>/jury/problems로 접속한 뒤, Import problems 버튼을 클릭하고 생성된 ZIP 파일을 문제별로 업로드합니다. 문제 목록에 등록된 후에는 'Admin' → 'Contests' → 해당 대회 편집 → Problems 탭에서 대회에 연결합니다. (대회 연결은 대회(Contest) 설정 페이지의 Step 4를 참고하세요.)

순서 작업 경로
1 문제 ZIP 업로드 Admin → Problems → Import problems
2 대회에 문제 연결 Admin → Contests → 해당 대회 편집 → Problems 탭

✅ Step 4. 테스트케이스 검증

문제를 업로드한 뒤 채점이 올바르게 동작하는지 반드시 확인합니다. 대회 당일이 아닌 리허설 전에 완료해야 당일 문제 발생을 막을 수 있습니다.

리허설 전 — 임시 대회로 전체 검증

DOMjudge에는 별도 검증 버튼이 없습니다. 아래 절차로 직접 확인합니다.

  1. 임시 대회 생성 — 본 대회와 별도로 검증용 Contest를 생성합니다. 시간은 넉넉하게 설정합니다.
  2. 문제 전체 연결 — 업로드된 모든 문제를 임시 대회의 Problems 탭에 연결합니다. 각 문제 설정에서 Lazy eval은 OFF로 설정하세요 — 오답이 발생해도 모든 테스트케이스를 끝까지 실행해 채점 데이터 전체를 한 번에 검증할 수 있습니다.
  3. 모범답안 제출 — Jury 계정(또는 별도 테스트 계정)으로 각 문제의 정답 코드를 직접 제출합니다.
  4. 전체 Accepted 확인 — 모든 문제가 Accepted로 채점되어야 정상입니다. 하나라도 오답·오류가 나오면 해당 문제의 테스트케이스와 시간제한을 점검합니다.
⚠ 잘못된 테스트케이스 주의

입력(.in) 또는 출력(.ans) 파일이 빈 파일(공백)인 경우, 채점기가 정상 채점을 하지 못해 참가자 전원이 오답 처리될 수 있습니다. 대회 도중 발견하면 복구가 어렵습니다.

업로드 전 반드시 모든 .in / .ans 파일에 내용이 있는지 확인하세요.

대회 중 테스트케이스 오류 발견 시

대회 진행 중 테스트케이스 오류가 확인된 경우, 아래 순서로 수정하고 재채점합니다.

  1. Admin → Problems → 해당 문제 편집에서 테스트케이스 항목을 직접 수정합니다. 잘못된 케이스는 삭제하고 올바른 .in / .ans 파일을 다시 등록합니다.
  2. 수정 완료 후 Rejudge all submissions 버튼을 클릭해 해당 문제의 전체 제출을 재채점합니다.
  3. 채점 대기열(Judging queue)이 비워지면 스코어보드에 자동 반영됩니다.
💡 팁: 재채점 중에도 대회는 계속 진행됩니다. 재채점 사실과 사유를 Clarification 전체 공지로 참가자에게 안내하는 것을 권장합니다.
