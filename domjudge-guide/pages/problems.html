문제(Problem) 준비

⚠ 문제 패키징 주의사항

DOMjudge는 표준 ICPC 문제 포맷(.zip)을 준수합니다. 각 패키지에는 반드시 problem.yaml 파일과 data/ 폴더(secret, sample 등)가 포함되어야 합니다.

📦 예시 문제 패키지 다운로드

아래 예시 문제를 DOMjudge에 바로 업로드하여 시스템 동작을 확인하거나 데모 대회에서 활용할 수 있습니다. 각 패키지는 표준 ICPC 포맷을 준수합니다.

👋 Hello World

입력 없이 Hello World 출력하기

problem-hello.zip ↓ ➕ 두 수의 합

두 정수 A, B를 입력받아 A+B를 출력하기

problem-aplusb.zip ↓ 🔍 최솟값 찾기

N개의 정수 중 최솟값 출력하기

problem-minval.zip ↓

※ 문제 설명 PDF는 포함되어 있지 않습니다. 데모 대회용으로만 활용하고, 실제 대회 문제는 직접 제작하세요.

🐍 excel2problems 스크립트로 문제 일괄 생성

엑셀에서 문제 내용과 테스트케이스를 작성하면 Word 문서(문제지) 생성 → PDF 변환 → DOMjudge ZIP 패키징까지 자동으로 처리합니다. 관리자는 자동 생성된 ZIP 파일을 Jury 페이지에서 가져오기만 하면 됩니다.

excel2problems 스크립트 다운로드

엑셀(xlsx) → Word(docx) → DOMjudge ZIP 변환 도구입니다. PDF 변환에 Microsoft Word 또는 LibreOffice가 필요합니다.

⬇ excel2problems.zip
① 템플릿 생성

ZIP 압축 해제 후 아래 명령어를 실행하면 problems_template.xlsx와 problem_template.docx가 생성됩니다.

python 1-excel2docx.py --template
💡 팁: 처음 사용하거나 전체 흐름을 먼저 테스트하려면 아래 명령어로 예시 문제 9개가 채워진 엑셀을 바로 생성할 수 있습니다. 
python create_example_problems.py
② 엑셀 작성

시트 1개 = 문제 1개입니다. 시트 이름이 problem_id가 되므로 영문으로 작성합니다. (예: aplusb, sort)

구역 열 주요 항목
메타데이터 A~B열 name, label, timelimit
문제 설명 D~E열 title, description, input_desc, output_desc
테스트케이스 G~I열 sample / secret 구분 후 입력·출력 작성 (셀 내 줄바꿈: Alt+Enter)
③ Word 문서 생성

엑셀을 저장하고 닫은 뒤 실행합니다. results/docx/에 문제별 .docx 파일이 생성됩니다.

python 1-excel2docx.py
④ Word 편집 (선택)

results/docx/의 파일을 열어 수식, 그림, 서식 등을 자유롭게 수정합니다. 테스트케이스는 별도 .json 파일에 보관되므로 docx를 수정해도 채점 데이터에는 영향이 없습니다.

⑤ ZIP 패키징

docx를 PDF로 변환한 뒤 DOMjudge ICPC ZIP 형식으로 패키징합니다. results/{label}-{problem_id}.zip 파일이 문제별로 생성됩니다.

python 2-problems2zip.py

※ PDF 변환에 Microsoft Word 또는 LibreOffice가 설치되어 있어야 합니다.

⑥ DOMjudge Import

브라우저에서 http://<domjudge-ip>/jury/problems로 접속한 뒤, Import problems 버튼을 클릭하고 생성된 ZIP 파일을 문제별로 업로드합니다.

1. 문제 패키지 구조

각 문제는 아래 구조를 가진 ZIP 파일로 패키징합니다. 한국어 문제의 경우 Docker 환경에서 LaTeX 한글 컴파일이 어려우므로, 외부에서 PDF를 완성한 뒤 삽입하는 방식을 사용합니다. 문제별로 PDF를 반드시 분리하여 넣어야 하며, 통합 PDF는 사용할 수 없습니다.

problem-a/
├── problem.yaml                  ← 문제 메타데이터
├── problem_statement/
│   └── problem.pdf               ← 외부에서 제작한 PDF
└── data/
    ├── sample/                   ← 공개 예제 (문제 PDF와 동일해야 함)
    │   ├── 1.in
    │   └── 1.ans
    └── secret/                   ← 채점용 비공개 테스트케이스
        ├── 1.in
        └── 1.ans

problem.yaml 형식

문제 이름과 시간제한을 지정합니다. 시간제한은 초 단위이며, Python에는 별도 Time factor가 자동으로 곱해집니다.

name: 문제 이름
timelimit: 2

2. 테스트 케이스 관리 및 검증

채점의 정확성을 위해 테스트 케이스 구성과 검증은 필수입니다.

  • 데이터 분리: data/sample(공개용)과 data/secret(비공개 채점용) 폴더로 명확히 분리합니다.
  • 검증(Validation): 업로드 직후 'Check' 버튼을 눌러 제출한 샘플 파일이 정답으로 처리되는지 테스트합니다.
  • Diff 확인: 출력이 일치하지 않는 경우, Compare 스크립트(default, float 등)가 적절한지 설정에서 확인하세요.

채점 방식 기본값: 참가자 출력과 정답 파일을 완전히 일치시키는 방식입니다. 정답이 유일한 문제로 출제하면 별도 설정 없이 기본값으로 충분합니다.
