1. 데이터베이스 백업 및 복원

서버 장애나 설정 오류 발생 시를 대비해 주기적으로 백업하고, 필요 시 복원합니다. 백업 파일은 외부 저장소나 USB에 보관하세요.

백업

docker exec domjudge-mariadb mysqldump \
  -u domjudge -pdomjudge_pass domjudge \
  > backup_$(date +%H%M).sql

복원

docker compose stop domserver
docker exec -i domjudge-mariadb mysql \
  -u domjudge -pdomjudge_pass domjudge \
  < backup_HHMM.sql
docker compose start domserver
⚠ 주의: 복원 전 domserver를 중단해야 진행 중인 채점과 충돌이 발생하지 않습니다. 복원 후 스코어보드와 제출 내역이 백업 시점으로 롤백됩니다.

3. Judging Lag 대응 절차

Judging Lag 기준(30초/1분/무한)은 스트레스 테스트 페이지를 참고하세요. 아래는 각 상황별 실제 대응 방법입니다.

1분 이상 — 채점기 확장 
docker compose up -d --scale judgehost=$(($(nproc) > 5 ? $(nproc) - 4 : 1))
무한 대기 — Judgehost 재시작 
docker compose restart judgehost

재시작 후에도 복구되지 않으면 아래 섹션 4의 락 정리 스크립트를 실행하세요.

4. Judgehost 데몬 락 정리 스크립트 (백업용)

비정상 종료로 인해 잔류한 데몬 락(Lock) 파일을 정리하여 Judgehost 재시작 오류를 해결합니다.

nano cleanup_judgehost_ids.sh
#!/bin/bash
# cleanup_judgehost_ids.sh (호스트용 고도화 버전)

# 1. 볼륨 마운트 포인트 확인 (에러 처리 추가)
VOLUME_PATH=$(docker volume inspect domjudge_judgehost-ids --format '{{.Mountpoint}}' 2>/dev/null)
if [ -z "$VOLUME_PATH" ]; then
    echo "오류: 볼륨을 찾을 수 없습니다."
    exit 1
fi

# 2. 현재 실행 중인 모든 컨테이너 ID(Full ID) 가져오기
RUNNING_IDS=$(docker ps -q --no-trunc)

echo "--- 락 정리 시작 ---"

# 3. 16자리 CID 파일들을 순회
# /shared/daemon-ids 내부에 16자리 파일명이 생성되므로 해당 경로 타겟팅
for file in $(find "$VOLUME_PATH" -maxdepth 1 -type f -regextype posix-extended -regex ".*/[a-f0-9]{16}"); do
    cid_short=$(basename "$file")

    # 실행 중인 전체 ID 목록에 이 짧은 ID가 포함되어 있는지 확인
    if ! echo "$RUNNING_IDS" | grep -q "^$cid_short"; then
        daemon_id=$(cat "$file")

        # 실제 삭제 작업
        rm -f "$file"
        rm -rf "$VOLUME_PATH/lock_$daemon_id"

        echo "정리 완료: 불필요한 ID=$cid_short (DAEMON_ID=$daemon_id) 삭제됨"
    fi
done

echo "--- 정리 완료 ---"
chmod a+x ./cleanup_judgehost_ids.sh
sudo ./cleanup_judgehost_ids.sh
