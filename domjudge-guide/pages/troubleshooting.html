트러블슈팅

1. 백업·복원 스크립트 파일 만들기

서버 장애나 설정 오류 발생 시를 대비해 주기적으로 백업하고, 필요 시 복원합니다. 아래 스크립트는 mariadb-data를 포함한 모든 도커 볼륨(데이터베이스, 제출 소스, 채점 결과, 문제 파일 등)을 통째로 tar.gz로 묶어 두었다가 그대로 되살립니다. 백업 파일은 외부 저장소나 USB에 보관하세요.

docker-compose.yml이 있는 폴더로 이동한 뒤, nano backup_volumes.sh 명령어로 아래 내용을 작성합니다.

cd ~/domjudge
nano backup_volumes.sh
#!/bin/bash

# 1. 백업 파일을 저장할 디렉토리 설정 (현재 경로의 offline_backup 폴더)
BACKUP_DIR="$(pwd)/offline_backup"
mkdir -p "$BACKUP_DIR"

echo "=============================================="
echo "호스트 직접 접근 방식 볼륨 백업을 시작합니다."
echo "저장 위치: $BACKUP_DIR"
echo "=============================================="

# 2. 존재하는 모든 도커 볼륨 이름 조회
VOLUMES=$(docker volume ls -q)

if [ -z "$VOLUMES" ]; then
  echo "백업할 도커 볼륨이 없습니다."
  exit 0
fi

# 3. 각 볼륨의 물리적 경로를 찾아 개별 압축
for vol in $VOLUMES; do
  # 볼륨이 호스트 OS에 마운트된 실제 경로 추출 (보통 /var/lib/docker/volumes/이름/_data)
  MOUNT_POINT=$(docker volume inspect "$vol" --format '{{ .Mountpoint }}')
  
  if [ -d "$MOUNT_POINT" ]; then
    echo "[진행 중] $vol 볼륨 백업..."
    # 호스트 OS의 tar를 사용하여 직접 압축 (root 권한 필수)
    sudo tar -czvf "${BACKUP_DIR}/${vol}_backup.tar.gz" -C "$MOUNT_POINT" . > /dev/null 2>&1
    echo "  -> 완료: ${vol}_backup.tar.gz"
  else
    echo "[오류] $vol 볼륨의 물리적 경로($MOUNT_POINT)를 찾을 수 없거나 접근할 수 없습니다."
  fi
done

echo "=============================================="
echo "모든 볼륨 백업이 완료되었습니다!"

이어서 nano restore_volumes.sh 명령어로 아래 내용을 작성합니다.

nano restore_volumes.sh
#!/bin/bash
# backup_volumes.sh 로 만든 <볼륨명>_backup.tar.gz 를 도커 볼륨으로 복원한다.
# Docker Desktop(WSL 백엔드)에서는 /var/lib/docker/volumes 에 호스트 직접 접근이 안 되므로
# 헬퍼 컨테이너(alpine)에 볼륨을 마운트해서 tar 로 풀어 넣는다.
#
# 사용법:
#   1) docker-compose.yml 이 있는 폴더(~/domjudge)로 이동
#   2) docker compose down            # 컨테이너 정지 (볼륨은 유지)
#   3) ./restore_volumes.sh <백업 폴더>   # 생략 시 ./offline_backup
#   4) docker compose up -d
set -euo pipefail

BACKUP_DIR="${1:-$(pwd)/offline_backup}"

if [ ! -d "$BACKUP_DIR" ]; then
  echo "백업 폴더를 찾을 수 없습니다: $BACKUP_DIR"
  exit 1
fi

echo "=============================================="
echo "도커 볼륨 복원을 시작합니다."
echo "백업 위치: $BACKUP_DIR"
echo "=============================================="

# compose 가 만든 이름/라벨 그대로 볼륨이 생기도록 먼저 컨테이너를 '생성만' 한다.
if [ -f docker-compose.yml ] || [ -f compose.yml ] || [ -f compose.yaml ] || [ -f docker-compose.yaml ]; then
  echo "[준비] docker compose create (볼륨 생성)"
  docker compose create >/dev/null 2>&1 || true
fi

shopt -s nullglob
FILES=("$BACKUP_DIR"/*_backup.tar.gz)
if [ ${#FILES[@]} -eq 0 ]; then
  echo "복원할 *_backup.tar.gz 파일이 없습니다."
  exit 0
fi

for f in "${FILES[@]}"; do
  base=$(basename "$f")
  vol="${base%_backup.tar.gz}"

  echo "[진행 중] $vol 볼륨 복원..."

  # 볼륨이 없으면 생성
  docker volume inspect "$vol" >/dev/null 2>&1 || docker volume create "$vol" >/dev/null

  # 기존 내용을 비우고 tar 를 풀어 넣는다 (백업은 -C <mountpoint> . 로 만들어져 ./ 상대경로임)
  docker run --rm \
    -v "$vol":/data \
    -v "$BACKUP_DIR":/backup:ro \
    alpine sh -c "rm -rf /data/* /data/..?* /data/.[!.]* 2>/dev/null; tar -xzpf /backup/$base -C /data"

  echo "  -> 완료: $vol"
done

echo "=============================================="
echo "모든 볼륨 복원이 완료되었습니다. 이제 'docker compose up -d' 를 실행하세요."

두 파일에 실행 권한을 부여합니다.

chmod +x backup_volumes.sh restore_volumes.sh

2. 백업하기

데이터가 기록되는 도중에 백업하면 파일이 깨질 수 있으므로, 먼저 컨테이너를 내린 뒤 백업하고 다시 올립니다. 볼륨 경로에 접근하기 위해 sudo 비밀번호를 묻습니다.

cd ~/domjudge
docker compose down
./backup_volumes.sh
docker compose up -d

완료되면 현재 폴더 아래 offline_backup/ 폴더에 볼륨별로 <볼륨명>_backup.tar.gz 파일이 생성됩니다. 이 폴더를 USB나 외부 저장소로 복사해 두세요.

ls -lh offline_backup/

3. 복원하기

복원할 서버의 ~/domjudge 폴더에 docker-compose.yml과 restore_volumes.sh가 있어야 합니다. 그 아래에 offline_backup/ 폴더를 만들고, 백업해 둔 <볼륨명>_backup.tar.gz 파일들을 USB나 외부 저장소에서 모두 복사해 넣습니다.

mkdir -p ~/domjudge/offline_backup
cp /media/usb/offline_backup/*_backup.tar.gz ~/domjudge/offline_backup/
ls -lh ~/domjudge/offline_backup/

파일이 모두 들어 있는지 확인했으면, 컨테이너를 내리고 복원한 다음 다시 올립니다.

cd ~/domjudge
docker compose down
./restore_volumes.sh
docker compose up -d

백업 폴더가 다른 위치에 있다면 경로를 인자로 넘깁니다.

./restore_volumes.sh /media/usb/offline_backup
⚠ 주의: 복원 스크립트는 같은 이름의 볼륨 내용을 모두 지운 뒤 백업본을 풀어 넣습니다. 반드시 docker compose down으로 컨테이너를 먼저 중단하세요. 볼륨 이름은 docker-compose.yml이 있는 폴더 이름(예: domjudge_mariadb-data)을 따르므로, 백업한 서버와 같은 폴더 이름(~/domjudge)에서 복원해야 합니다.

5. Judging Lag 대응 절차

Judging Lag 기준(30초/1분/무한)은 스트레스 테스트 페이지를 참고하세요. 아래는 각 상황별 실제 대응 방법입니다.

1분 이상 — 채점기 추가

DOMjudge 설치 페이지의 3. docker-compose.yml 작성 섹션에 있는 judgehost 개별 선언 방식을 참고하여, docker-compose.yml에 judgehost 블록을 하나 더 추가합니다. 서비스 이름과 DAEMON_ID는 기존 값과 겹치지 않게 하나씩 늘리고, 총 개수는 nproc - 4를 넘기지 마세요.

cd ~/domjudge
nano docker-compose.yml

저장한 뒤 다시 올리면 기존 컨테이너는 그대로 두고 새로 추가한 judgehost만 시작됩니다.

docker compose up -d
무한 대기 — Judgehost 재시작

judgehost 서비스가 여러 개이므로 이름을 하나씩 나열하는 대신 grep으로 모아서 한 번에 재시작합니다.

cd ~/domjudge
docker compose restart $(docker compose ps --services | grep judgehost)
