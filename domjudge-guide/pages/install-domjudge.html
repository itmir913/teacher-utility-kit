DOMjudge 설치 (Docker Compose)

1. 설치 디렉토리 준비

설치에 필요한 설정 파일들을 보관할 전용 디렉토리를 생성하고 이동합니다.

mkdir -p ~/domjudge && cd ~/domjudge

2. docker-compose.yml 작성

nano docker-compose.yml 명령어로 아래 설정 내용을 작성합니다.

nano docker-compose.yml
services:
  mariadb:
    image: mariadb:10.11
    container_name: domjudge-mariadb
    restart: always
    environment:
      - MYSQL_ROOT_PASSWORD=domjudge_root_pass
      - MYSQL_USER=domjudge
      - MYSQL_PASSWORD=domjudge_pass
      - MYSQL_DATABASE=domjudge
      - TZ=Asia/Seoul
      - CONTAINER_TIMEZONE=Asia/Seoul
    ports:
      - 13306:3306
    command: --max-connections=1000 --max-allowed-packet=512M --innodb_snapshot_isolation=OFF
    volumes:
      - mariadb-data:/var/lib/mysql

  domserver:
    image: domjudge/domserver:9.0.0
    container_name: domjudge-domserver
    restart: always
    depends_on:
      - mariadb
    ports:
      - "80:80"
    environment:
      - MYSQL_HOST=mariadb
      - MYSQL_USER=domjudge
      - MYSQL_PASSWORD=domjudge_pass
      - MYSQL_DATABASE=domjudge
      - MYSQL_ROOT_PASSWORD=domjudge_root_pass
      - CONTAINER_TIMEZONE=Asia/Seoul
      - PHP_MEMORY_LIMIT=512M
      - PHP_MAX_CHILDREN=80
    volumes:
      - domserver-data:/opt/domjudge/domserver/etc
      - domserver-submissions:/opt/domjudge/domserver/submissions

  judgehost:
    image: domjudge/judgehost:9.0.0
    restart: always
    privileged: true
    cgroup: host
    depends_on:
      - domserver
    environment:
      - DOMSERVER_URL=http://domserver/api
      - JUDGEDAEMON_PASSWORD=your_password  # 실제 비밀번호로 변경하세요
      - CONTAINER_TIMEZONE=Asia/Seoul
    volumes:
      - /sys/fs/cgroup:/sys/fs/cgroup:rw
      - judgehost-ids:/shared/daemon-ids
    entrypoint:
      - /bin/bash
      - -c
      - |
        SHARED=/shared/daemon-ids
        mkdir -p $$SHARED

        # 1. 컨테이너 고유 ID 추출 (16자리)
        MY_ID=$$(cat /proc/self/cgroup | grep -o "[a-f0-9]\{64\}" | head -1 | cut -c1-16)

        # 2. 종료 시 실행될 정리 함수 (Trap)
        cleanup() {
            echo "[judgehost] 종료 신호 감지, DAEMON_ID=$$DAEMON_ID 정리 중..."
            rm -f "$$SHARED/$$MY_ID"
            rm -rf "$$SHARED/lock_$$DAEMON_ID"
            echo "[judgehost] 정리 완료. 종료합니다."
            exit 0
        }
        # SIGTERM 및 SIGINT 신호 대기
        trap cleanup SIGTERM SIGINT

        # 3. DAEMON_ID 할당 및 재사용 로직
        if [ -f "$$SHARED/$$MY_ID" ]; then
            export DAEMON_ID=$$(cat $$SHARED/$$MY_ID)
            echo "[judgehost] 기존 DAEMON_ID=$$DAEMON_ID 재사용"
        else
            for i in $$(seq 0 99); do
                if mkdir "$$SHARED/lock_$$i" 2>/dev/null; then
                    export DAEMON_ID=$$i
                    echo $$i > "$$SHARED/$$MY_ID"
                    echo "[judgehost] 새 DAEMON_ID=$$DAEMON_ID 배정"
                    break
                fi
            done
        fi

        # 4. 실제 프로세스 실행 (백그라운드로 실행 후 wait로 trap 대기)
        /scripts/start.sh &
        # 마지막 백그라운드 프로세스가 끝날 때까지 대기
        wait $$!

volumes:
  mariadb-data:
  domserver-data:
  domserver-submissions:
  judgehost-ids:

3. 서비스 실행 및 비밀번호 설정

1

서버 및 DB 구동

먼저 DB와 웹 서버를 실행합니다. 초기화에는 약 30초가 소요됩니다.

docker compose up -d mariadb domserver
2

Judgehost API 비밀번호 확인

Judgehost가 서버에 접속할 때 필요한 API 비밀번호를 확인합니다.

docker exec -it domjudge-domserver cat /opt/domjudge/domserver/etc/restapi.secret

💡 위 명령어로 출력된 내용 중 마지막의 랜덤 문자열을 복사하여 docker-compose.yml의 JUDGEDAEMON_PASSWORD 항목에 붙여넣으세요.

Judgehost 비밀번호를 docker-compose.yml에 입력하였다면, 전체 서비스를 다시 올립니다. 

docker compose up -d

아래 명령어를 입력하여 로그를 확인해보세요. judgehost가 정상적으로 동작하는지 확인해야 합니다. 

docker compose logs judgehost
3

초기 관리자(admin) 계정 정보 확인

DOMjudge v9.0.0의 초기 관리자 아이디는 admin입니다.
비밀번호는 보안을 위해 설치 시 랜덤으로 생성되므로, 아래 명령어를 실행하여 생성된 비밀번호를 확인해야 합니다.

웹 UI(Jury Interface) 접속을 위한 랜덤 비밀번호 확인 명령어:

docker exec -it domjudge-domserver cat /opt/domjudge/domserver/etc/initial_admin_password.secret
4

전체 서비스 재시작 및 확장(Scaling)

DOMjudge는 CPU 코어당 하나의 채점기(Judgehost)를 배정하여 운영하는 것을 권장합니다. 채점기를 여러 개 구동하면 대량의 제출이 발생했을 때 병렬 처리가 가능하여 대기 시간을 획기적으로 줄일 수 있습니다.

💡 코어 배분 전략:
모든 코어를 채점에 사용하면 DB(MariaDB)와 웹 서버(Domserver)가 가용 자원을 확보하지 못해 시스템이 느려질 수 있습니다. 따라서 전체 코어 중 2~4개 정도는 시스템 유지용으로 남겨두고 나머지를 채점기에 할당하는 것이 가장 안정적입니다.
(예: 16코어 서버의 경우 약 12개의 채점기 할당 권장)

아래 명령어는 시스템 코어(nproc)를 체크하여 자동으로 최적의 개수만큼 채점기를 실행합니다(단, 재부팅하면 --scale 옵션은 자동 적용되지 않습니다.)

# 1. CPU 코어 개수 확인
nproc

# 2. 시스템 안정성을 위해 4개 코어를 제외하고 채점기 확장 실행
# (코어가 5개 이하면 최소 1개 실행, 그 이상이면 전체 코어 - 4개 실행)
docker compose up -d --scale judgehost=$(($(nproc) > 5 ? $(nproc) - 4 : 1))

🆔 DAEMON ID 중복 방지 안내

여러 개의 채점기를 동시에 돌릴 때는 각 컨테이너마다 고유한 DAEMON ID를 부여받아야 합니다. 이 부분은 앞서 docker-compose.yml의 entrypoint에 작성된 스크립트가 컨테이너 생성 시 빈 ID를 자동으로 찾아 할당하므로 별도의 수동 설정이 필요 없습니다.

✅ 최종 확인 사항

  • docker compose logs judgehost | grep "DAEMON_ID" 명령으로 각 채점기가 서로 다른 ID로 활성화되었는지 확인합니다.
  • 관리자 페이지(Jury Interface) → Judgehosts 메뉴에서 확장된 개수만큼의 항목이 'Enabled' 상태인지 확인합니다.
