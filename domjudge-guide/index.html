설치

1

패키지 업데이트 및 Docker 설치

Docker 공식 스크립트로 엔진을 구성하고 현재 사용자에게 권한을 부여합니다.

bash 
# 패키지 업데이트 및 유틸리티 설치
sudo apt update && sudo apt upgrade -y
sudo apt install -y htop cpufrequtils curl openssh-server

# Docker 공식 설치 스크립트
curl -fsSL https://get.docker.com -o get-docker.sh
sudo sh get-docker.sh

# 현재 사용자 Docker 권한 부여
sudo usermod -aG docker $USER
newgrp docker        # 즉시 권한 적용
docker --version     # 설치 확인

실행 환경

사용자: judge

Compose: v2.x 내장

2

SSH 포트 변경 및 타임존 설정

bash 
# /etc/ssh/sshd_config 에서 Port 22 → Port 22222
sudo nano /etc/ssh/sshd_config

sudo systemctl restart ssh
ss -antp | grep 22222    # 포트 확인

# 타임존 KST 설정
sudo timedatectl set-timezone Asia/Seoul && date
주의: SSH 포트 변경 전 UFW에서 먼저 허용 → sudo ufw allow 22222/tcp

스왑 메모리(16 GB) 및 CPU 성능 모드

bash 
# 스왑 파일 생성 (16 GB)
sudo fallocate -l 16G /swapfile
sudo chmod 600 /swapfile
sudo mkswap /swapfile
sudo swapon /swapfile
echo '/swapfile none swap sw 0 0' | sudo tee -a /etc/fstab
free -h

# CPU Performance 모드 고정
echo 'GOVERNOR="performance"' | sudo tee /etc/default/cpufrequtils
sudo systemctl restart cpufrequtils
cat /sys/devices/system/cpu/cpu0/cpufreq/scaling_governor

Section 3

설정 — docker-compose.yml

비밀번호 3종 필수 변경: domjudge_root_pass domjudge_pass JUDGEDAEMON_PASSWORD — JUDGEDAEMON_PASSWORD는 실행 섹션 Step 2에서 확인 후 입력합니다.
docker-compose.yml 
services:

  mariadb:
    image: mariadb:10.11
    container_name: domjudge-mariadb
    restart: always
    environment:
      - MYSQL_ROOT_PASSWORD=domjudge_root_pass   # ← 변경
      - MYSQL_USER=domjudge
      - MYSQL_PASSWORD=domjudge_pass           # ← 변경
      - MYSQL_DATABASE=domjudge
      - TZ=Asia/Seoul
      - CONTAINER_TIMEZONE=Asia/Seoul
    ports:
      - 13306:3306
    command: --max-connections=1000 --max-allowed-packet=512M --innodb_snapshot_isolation=OFF
    volumes:
      - mariadb-data:/var/lib/mysql

  domserver:
    image: domjudge/domserver:9.0.0
    container_name: domjudge-domserver
    restart: always
    depends_on: [mariadb]
    ports:
      - "80:80"
    environment:
      - MYSQL_HOST=mariadb
      - MYSQL_USER=domjudge
      - MYSQL_PASSWORD=domjudge_pass
      - MYSQL_DATABASE=domjudge
      - MYSQL_ROOT_PASSWORD=domjudge_root_pass
      - CONTAINER_TIMEZONE=Asia/Seoul
      - PHP_MEMORY_LIMIT=512M
      - PHP_MAX_CHILDREN=80
    volumes:
      - domserver-data:/opt/domjudge/domserver/etc
      - domserver-submissions:/opt/domjudge/domserver/submissions

  judgehost:
    image: domjudge/judgehost:9.0.0
    restart: always
    privileged: true
    cgroup: host
    depends_on: [domserver]
    environment:
      - DOMSERVER_URL=http://domserver/api
      - JUDGEDAEMON_PASSWORD=your_password  # ← Step 2에서 확인
      - CONTAINER_TIMEZONE=Asia/Seoul
    volumes:
      - /sys/fs/cgroup:/sys/fs/cgroup:rw
      - judgehost-ids:/shared/daemon-ids
    entrypoint:
      - /bin/bash
      - -c
      - |
        SHARED=/shared/daemon-ids; mkdir -p $$SHARED
        MY_ID=$$(cat /proc/self/cgroup|grep -o "[a-f0-9]\{64\}"|head -1|cut -c1-16)
        cleanup(){ rm -f "$$SHARED/$$MY_ID"; rm -rf "$$SHARED/lock_$$DAEMON_ID"; exit 0; }
        trap cleanup SIGTERM SIGINT
        if [ -f "$$SHARED/$$MY_ID" ]; then
          export DAEMON_ID=$$(cat $$SHARED/$$MY_ID)
        else
          for i in $$(seq 0 99); do
            if mkdir "$$SHARED/lock_$$i" 2>/dev/null; then
              export DAEMON_ID=$$i; echo $$i>"$$SHARED/$$MY_ID"; break
            fi
          done
        fi
        /scripts/start.sh & wait $$!

volumes:
  mariadb-data:
  domserver-data:
  domserver-submissions:
  judgehost-ids:

Section 4

서비스 실행 및 검증

⚠ 순서 준수 필수: DOMjudge는 API 비밀번호를 동적으로 생성합니다. 아래 5단계를 반드시 순서대로 진행하세요.
1

DB + DOMserver 먼저 구동

bash 
docker compose up -d mariadb domserver
# DB 초기화 대기 약 30초
docker compose logs domserver | tail -20
2

Judgehost API 비밀번호 확인

bash 
docker exec -it domjudge-domserver \
  cat /opt/domjudge/domserver/etc/restapi.secret
출력: default http://domserver/api judgehost a8kXm2... — 마지막 문자열 복사

출력 예시

...judgehost
xK9mP3qR7tY2wL

→ compose.yml의
JUDGEDAEMON_PASSWORD에 붙여넣기

3

비밀번호 반영 후 전체 실행

JUDGEDAEMON_PASSWORD 수정 후 저장

bash 
docker compose up -d
4

초기 admin 비밀번호 확인

bash 
docker exec -it domjudge-domserver \
  cat /opt/domjudge/domserver/etc/initial_admin_password.secret
확인 후 http://192.168.0.100/ 에서 admin 계정 로그인
5

Judgehost 스케일 아웃

bash 
# CPU 코어 수 확인
nproc

# (nproc-4)와 1 중 더 큰 값으로 스케일 아웃
docker compose up -d \
  --scale judgehost=$(( $(nproc) > 5 ? $(nproc) - 4 : 1 ))

# DAEMON_ID 중복 없이 등록됐는지 확인
docker compose logs judgehost | grep "DAEMON_ID"
# 관리자 페이지 → Jury → Judgehosts 에서 확인

실행 결과

nproc = 16

→ judgehost = 12개

Jury 등록: 12 active

Judging Lag
평균 3초 유지 ✓

스트레스 테스트 시나리오

단계 유형 방법 목표
1단계 동시 접속 전원 메인 페이지 무한 새로고침 Nginx 안정성
2단계 대량 제출 정답 코드 10초간 연속 제출 Judging Lag 측정
3단계 무한 루프 while(1); 제출 TLE 판정
4단계 메모리 폭탄 거대 배열 선언 제출 MLE + Swap 확인

운영 명령어

채점기 확장

bash 
docker compose up -d \
  --scale judgehost=12

DB 백업

bash 
docker exec domjudge-mariadb \
  mysqldump -u domjudge \
  -pdomjudge_pass domjudge \
  > backup_$(date +%H%M).sql

Section 5

트러블슈팅

Judgehost가 관리자 페이지에 나타나지 않음

원인: JUDGEDAEMON_PASSWORD가 restapi.secret과 불일치

bash 
# 비밀번호 재확인
docker exec -it domjudge-domserver \
  cat /opt/domjudge/domserver/etc/restapi.secret

# 수정 후 재시작
docker compose up -d judgehost
docker compose logs judgehost | tail -30
Cgroup 오류로 Judgehost 실행 실패

원인: cgroup v2 비활성 또는 볼륨 내 고아 락 파일 잔존

bash 
# cgroup v2 확인
cat /sys/fs/cgroup/cgroup.controllers

# 고아 락 파일 정리
VPATH=$(docker volume inspect domjudge_judgehost-ids \
  --format '{{.Mountpoint}}')
RUNNING=$(docker ps -q --no-trunc)
for f in $(find "$VPATH" -maxdepth 1 -type f \
  -regextype posix-extended -regex ".*/[a-f0-9]{16}"); do
  cid=$(basename "$f")
  if ! echo "$RUNNING" | grep -q "^$cid"; then
    did=$(cat "$f"); rm -f "$f"; rm -rf "$VPATH/lock_$did"
    echo "정리: CID=$cid DAEMON_ID=$did"
  fi
done
